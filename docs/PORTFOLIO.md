# 九注覆盖实验

目标是每期固定九注、18 元，提高至少一注中任意奖的覆盖率。它是独立替代组合，不增加原九模型实验的注数，也不是第十个模型。Laya 仍单独选择一注。

## 算法与口径

`back-coverage-v1` 保留原九模型每模型第 1 注的前区，只调整后区。固定前区后枚举全部 C(35,5)=324,632 种前区开奖：

1. 有任意一票前区命中至少三个时，所有 66 种后区开奖均至少有一奖。
2. 否则，将前区恰中两个的票的后区号码取并集 H；与 H 相交的后区开奖均中奖。
3. 其余后区开奖中，原九票的不同后区号码对只计一次：即后区全中、前区零或一个的奖。

每个前区命中模式可精确计算 `66 - C(12-|H|,2) + 不与H相交的不同选票后区对数`，最终除以 21,425,712。这个计数包含多票重叠，不使用“九票中奖事件独立”的近似。上述任意奖条件在本次已核验的 2026 年区间内适用。

三轮固定顺序坐标搜索：每票尝试后区全部 66 对，只接受严格增加中奖开奖总数的修改。确定性、有限耗时且覆盖率不低于输入；不声称全局最优。更改搜索规则需要新版本，不能覆盖已存档的预测。

均匀独立开奖是理论计算的假设。提高中奖并集可能减少同期开奖多票同时中奖；它不提高单票边际中奖概率，不意味着期望奖金增加，也不等于回本或盈利概率。

## 记录与核对

- 原 `predictions` / `results` 的实验语义不变。独立表 `portfolio_runs` 保存源候选、SHA-256、版本、生成时间、历史截止期、预算和新组合。
- 仅允许在下一期停售截止前生成前瞻方案；数据源断流时也不得事后补一套冒充前瞻。已有快照不可覆盖；开奖后导出只追加命中核对。
- 已有覆盖快照的期号，predict 的 `--force` 会在任何删除/训练前明确拒绝，以免改写已冻结方案的源候选。重新实验须引入独立预测版本；普通幂等执行仍可读取原快照。
- 历史模拟仅取统计报告中九模型共同的已核验期号；不读取目标开奖号进行优化。它仍是开奖后的探索性模拟，不构成提前发布证据。
- 覆盖实验只比较中奖事件和期数，不用未核准的奖金估算计算收益优势。

初次冻结模拟为 **26059—26117，共 59 期**：原九注 **35/59** 期至少一注中奖，覆盖组合 **30/59**。实际历史表现较差，不能用理论改善代替这个事实，也没有据此再次调参挑选更好看的回测版本。

首个真实前瞻方案为 **26118**，每套均九注18元：原组合理论覆盖 **47.0068%**，新组合 **48.2754%**，增加 **1.2685 个百分点**。截至生成时前瞻已核对为零期，后续开奖继续验证。两套组合均分别对 21,425,712 种合法开奖做过独立穷举复核。

## 操作

```bash
# Before the next draw; never modifies original model tickets.
python -m backend.src.tasks.portfolio --issue 26118

# Exploratory simulations only for verified common issues.
python -m backend.src.tasks.portfolio --backtest

# Settle existing snapshots and export portfolio.json, alongside other exports.
python -m backend.src.export.to_json

python -m unittest backend.tests.test_portfolio -v
```

predict 正常结束时自动生成独立方案；export 自动核对并保存 `data/export/portfolio.json`，现有 workflow 已会提交该 JSON 与 DB，前端发布流程会复制它。首页按期号匹配，旧期数据不会显示成本期方案。未生成或请求失败时显示待生成，并保留原九模型页面。
